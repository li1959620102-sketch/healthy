# AI 智参健康管理平台

> 中型、面向线上运行的 AI 健康管理平台（项目周期：2024-10 至 2025-04）。

本仓库是平台应用服务代码快照，不是一次性 Demo。系统围绕“健康测评 → 风险报告 → 食养计划 → 执行打卡 → 营养师复核”的业务闭环建设，支持多角色、异步报告生成、流式对话、知识库检索、对象存储和运营分析。

## 项目事实

| 维度 | 说明 |
|---|---|
| 项目周期 | 2024-10-01 至 2025-04-30，共 7 个自然月（212 天） |
| 项目类型 | 已上线运行的中型 AI 健康管理平台 |
| 正式智能体 | 6 个，全部进入产品目录并启用 |
| 负责模块 | 营养师智能体：RAG、多轮上下文、健康档案、拒答策略、人工营养师转接 |
| 核心存储 | MySQL、Redis、MinIO、Milvus |
| 接口形态 | REST API、SSE 流式输出、短票鉴权、对象存储预签名 URL |
| 质量保障 | 单元测试、集成测试、部署后冒烟测试、生产配置校验 |

## 智能体目录

1. 健康测评智能体：问卷、指标和风险分层。
2. 智能荐菜智能体：体质、慢病、过敏和预算约束下的菜品推荐。
3. 食养食疗智能体：周期方案、菜谱和采购清单。
4. 健康管家智能体：风险、用餐和打卡提醒。
5. 营养师智能体：营养问答、RAG、多轮对话和人工服务衔接。
6. 数据分析智能体：安全 Text2SQL、行级权限、图表和运营看板。

项目没有额外的 Supervisor/主 Agent。`ChatQueryService` 是共享编排服务，负责检索、拒答、上下文组装和模型流式输出；营养师智能体是面向用户的核心入口，不应把共享服务误写成第 7 个 Agent。

采购清单、OCR、旅行建议和截图导出属于业务扩展能力；未接入第三方供应商或专用引擎的部分会返回明确状态，不伪造已完成结果。

## 数据口径

当前仓库附带的 `test_db` 是开发/集成测试库，盘点结果约为 1,546 条基础表记录、1.89 MiB，不能作为线上生产规模。

生产数据必须从线上数据库、监控平台或数据仓库统计，并通过 `dataset_provenance` 登记来源、周期、行数和校验摘要。仓库提供生产规模容量基线生成器，但生成数据统一标记为 `synthetic`，禁止在简历或面试中称为真实用户数据。

## 启动和验证

```bash
# 本地测试
python -m pytest -q

# 生产配置校验与部署
docker compose -f docker-compose.production.yml config
docker compose -f docker-compose.production.yml up -d --build

# 部署后冒烟测试
set SMOKE_BASE_URL=https://your-production-domain.example
python -m pytest tests/smoke -q
```

生产环境禁止默认密钥、通配符 CORS、演示短信和演示账号。上线声明必须与实际发布记录、域名、监控、备份和回滚证据一致。
